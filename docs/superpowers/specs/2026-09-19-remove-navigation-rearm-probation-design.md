# 移除导航命令零速恢复试用期

## 目标

移除导航速度包被拒绝后必须连续发送至少 100 ms 零速度包才能恢复的机制。非法速度包仍应被整包拒绝，但下一帧合法速度包（包括非零速度包）必须立即恢复导航控制输出。

## 范围

- 修改 `NavHostLink` 内的 `ChassisCommandTracker`。
- 更新对应主机侧单元测试，覆盖拒包后和超时后的立即恢复行为。
- 不修改通信协议、速度边界、速度归一化、DR16 门控、双板 CAN 协议或 YAML 模块装配。

## 行为设计

### 合法命令

收到所有字段均为有限值，且满足 `|vx| <= 2.5 m/s`、`|vy| <= 2.5 m/s`、`|vw| <= 1.8 rad/s` 的命令时，跟踪器立即接受该命令：

- 设置 `finite_ = true`；
- 设置 `armed_ = true`；
- 刷新最后合法命令时间；
- 设置已收到合法命令标志；
- 增加 `accepted_count_`。

合法命令不需要为零速度，也不需要经过观察期。

### 非法命令

收到包含非有限字段或速度越界的命令时：

- 设置 `finite_ = false`；
- 增加 `rejected_count_`；
- 不刷新最后合法命令时间；
- 不改变 `armed_`。

因此，单个非法包不会立即撤销此前仍处于 150 ms 有效期内的合法命令。已有看门狗会在最后一帧合法命令达到 150 ms 后解除使能，避免长期沿用陈旧命令。

### 超时恢复

最后一帧合法命令达到 150 ms 后，跟踪器继续设置 `armed_ = false`。超时后的下一帧任意合法命令立即重新使能，无需先发送零速度包。

## 删除内容

- `COMMAND_REARM_PROBATION_MS`；
- `COMMAND_REARM_MAX_HEARTBEAT_GAP_MS`；
- 零速度判定函数；
- 试用期开始时间、最近零速度时间及试用期状态；
- 非法包重置试用期的相关分支。

## 测试策略

采用测试驱动开发：

1. 先修改跟踪器测试，要求初始合法非零命令立即接受；
2. 要求非法包被拒绝并增加拒绝计数，但不撤销仍新鲜的合法命令；
3. 要求非法包后的下一帧合法非零命令立即接受；
4. 要求 150 ms 超时后，下一帧合法非零命令立即接受；
5. 先确认新测试在旧实现上按预期失败，再修改生产代码并运行相关回归测试。

## 验收标准

- 不再存在 100 ms 零速度恢复时间或 50 ms 零包间隔约束；
- 非法包仍被整包拒绝并计数；
- 拒包后的下一帧合法非零命令立即使 `armed_` 恢复为真并增加接受计数；
- 150 ms 命令超时机制继续有效；
- `NavHostLink` 与导航协议相关主机侧测试全部通过；
- 不产生固件通信 ABI 变化。
